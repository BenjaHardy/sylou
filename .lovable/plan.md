# Extend Article 50(2) AI markers to remaining SharedReport tabs

## Goal

Apply the same machine-readable AI-generation markers established for the FLOW Report tab to the other three tabs of `/report/:token`, so the disclosure reflects what is AI-generated **on the currently visible tab**, and so human-authored content is never falsely marked as synthetic.

Frontend-only. No backend, schema, or edge-function changes.

## Per-tab analysis

| Tab | Content | AI? |
|---|---|---|
| **FLOW Report** | Radar, ScoreCards, Overall Summary, Key User Contributions | Yes (already marked) |
| **FLOW Report** | `FlowInfoSection`, `SelfAssessmentDisplay`, `TokenUsageSection`, `ProjectActivitySection` | No (outside wrapper) |
| **FLOW Profile** | `FlowWorkProfile` card when `source === "ai"` (archetype selected by AI scores) | Yes — mark |
| **FLOW Profile** | `FlowWorkProfile` card when `source === "pre"` or `"post"` | No — do NOT mark |
| **FLOW Profile** | Public-domain painting (`ProfilePaintingReveal`) inside the card | No — explicit negative marker |
| **FLOW Profile** | `FlowInfoSection`, `SelfAssessmentDisplay`, `TokenUsageSection`, `ProjectActivitySection`, imported-docs notices | No |
| **Writing** | User's TipTap snapshot | No |
| **Replay** | Sanitized rrweb-style snapshot of user activity | No |

## Changes in `src/pages/SharedReport.tsx`

### 1. Per-tab section constants

```ts
const AI_GENERATED_SECTIONS = {
  report: "ai-assessment",
  profile: "ai-profile-selection",
} as const;
```

Writing and Replay are intentionally absent.

### 2. Make the `<head>` meta-tag effect tab-aware

- On `report`: inject the three meta tags with `ai-generated-sections="ai-assessment"`.
- On `profile`: inject them only when the profile sub-tab is `source === "ai"`, using `ai-generated-sections="ai-profile-selection"`. Toggling to pre/post removes them.
- On `writing` or `replay`: inject nothing; cleanup removes any prior tags.

Lift `source` state from `ProfileTabContent` into `SharedReport` (controlled prop) so the effect can depend on `[report?.model_used, activeTab, profileSource]`.

### 3. Wrap the AI-derived profile card

In `ProfileTabContent.tsx`, conditionally wrap **only** the profile card block (the `<div key={source} className="animate-card-flip space-y-4">` containing the heading + `<FlowWorkProfile>`) in a `<section data-ai-generated="true" data-ai-model={aiModelName} aria-label="AI-derived collaboration profile">` when `source === "ai"`. For pre/post, render the same block without the wrapper. `aiModelName` becomes a new prop passed down from `SharedReport`.

`FlowInfoSection`, `SelfAssessmentDisplay`, `TokenUsageSection`, `ProjectActivitySection`, and imported-docs notices stay outside the wrapper.

### 4. Explicit negative marker on the painting

The public-domain painting rendered by `ProfilePaintingReveal` ends up as a DOM descendant of the AI-marked `<section>` (it sits inside the same `<Card>` as the archetype code/name and pillar tiles). Restructuring it out of the wrapper would require splitting the card visually, which is a layout regression risk.

Minimal fix: in `src/components/flow-report/ProfilePaintingReveal.tsx`, add `data-ai-generated="false"` to the **root element of both states** (the placeholder `<button>` and the revealed `<div className="flex flex-col items-center gap-3 pt-2 animate-fade-in">`). This explicitly tells any well-behaved content-provenance scanner that the painting and its caption metadata are not AI-generated, even though they live inside a section marked as containing AI content.

No visual change. The negative marker only attaches to the painting reveal's root; the surrounding card chrome (code, name, tagline, pillar tiles) remains correctly marked as AI-derived via the ancestor `<section>`.

### 5. Writing tab and Replay tab — explicitly no markers

No DOM changes needed; the tab-aware effect from step 2 ensures no meta tags are present while those tabs are active.

## Out of scope

- Footer "Generated by Sylou …" provenance block
- `FlowInfoSection`, `SelfAssessmentDisplay`, `TokenUsageSection`, `ProjectActivitySection`
- Radar visuals, score values themselves
- `FlowReplayOverlay` internals (sanitized user activity)
- Restructuring `FlowWorkProfile` to render the painting outside the card (deferred — negative marker is sufficient)
- Database schema, edge functions, report generation pipeline

## Verification

1. **Report tab**: three meta tags exist with `content="ai-assessment"`; existing `<section>` wrapper preserves the visual layout exactly.
2. **Profile tab, `source = "ai"`**: meta tags update to `content="ai-profile-selection"`; profile card carries `data-ai-generated="true"` and `data-ai-model`; the painting reveal root carries `data-ai-generated="false"` (verified in DevTools in both collapsed and revealed states).
3. **Profile tab, sub-tab pre/post**: meta tags removed from `<head>`; profile card has no `data-ai-*` attributes; painting's `data-ai-generated="false"` still present (harmless — no ancestor claims otherwise).
4. **Writing / Replay**: no `ai-generated` / `ai-model` / `ai-generated-sections` meta tags in `<head>`; no `data-ai-generated="true"` attributes in rendered content.
5. Visual diff each tab against current main — no layout regression, painting reveal still toggles correctly.
