# Root cause

Not a race. The `context-prompt` edge function omits the `concise_mode` column on every message it inserts (Ask prompt/response, Propose prompt/response, the `writing_summary` companion, and the Propose-confirm path). Because the DB default is `false`, those rows always read `concise_mode = false` in the export — regardless of the toggle state at send time. The plain `chat` path in `supabase/functions/chat/index.ts` already does this right; `context-prompt` simply forgot to.

Secondary gap: the Propose-confirm POST from the client doesn't carry `concise_mode` in its body at all.

Verified separately: the writing-summary LLM call (LLM #1, lines 701–711) runs *before* `conciseMode` is parsed (line 731), and `CONCISE_MODE_MODIFIER` is only ever appended to the LLM #2 `systemPrompt` (lines 809–811). Summary generation is genuinely unaffected by the toggle, so the `writing_summary` row must continue to record `concise_mode = false` to reflect what actually happened.

# Fix

## 1. `src/components/TextSelectionWindow.tsx`
Add `concise_mode: conciseMode ?? false` to the two Propose-confirm bodies:
- `handleAccept` (~line 487, `confirm: true`)
- `handleAcceptModified` (~line 529, `confirm: true, modified: true`)

The streaming POST (~line 295) already sends it; no change there. The reject body needs nothing.

## 2. `supabase/functions/context-prompt/index.ts`

**Confirm branch (~line 523):** parse the value once at the top of the branch, before any insert:
```ts
const conciseMode: boolean = body.concise_mode ?? false;
```
Then add `concise_mode: conciseMode` to:
- `propose_prompt` insert (~line 558)
- `propose_response` `responseMsgRow` (~line 578)

Leave the `writing_summary` insert in this branch (~line 568) **without** `concise_mode` — i.e. it stays at the DB default `false`. Add a one-line comment explaining why (summary was generated by LLM #1, which ignores the concise modifier).

**Non-confirm branch (`conciseMode` already in scope at line 731):** add `concise_mode: conciseMode` to:
- Streaming Ask path: `ask_prompt` (~967), `askResponseRow` `ask_response` (~987)
- Non-streaming Ask paths (~1425/1437 and ~1515/1527): the `ask_prompt` and `ask_response` inserts

Leave the three `writing_summary` inserts in this branch (~977, ~1431, ~1521) **without** `concise_mode`, same reason as above. Add the same one-line comment on each.

## Out of scope
- `default_concise_mode` seeding in `ProjectContentArea` — the symptom is independent of seeding; leave it.
- DB default — keep `false`; we set the value explicitly on the inserts that need to reflect the toggle.
